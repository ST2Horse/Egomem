## 一、一句话抓住课题本质（Research Story）

如果用一句话向审稿人或同学讲清这个课题：
> **AI 智能眼镜的长期记忆系统会把环境中路过的文字（墙上便签、海报、屏幕）转写成文本存入记忆，但在“看 → 存 → 查 → 答”的链路中丢失了“谁写的（Provenance/Source）”这一关键元数据，导致攻击者只需在物理世界贴一张纸，就能篡改用户记忆甚至向 AI 助手下达隐蔽指令；我们系统测量了来源在五段漏斗中的丢失机制，并提出双层防御框架 EgoMemGuard。**

### 为什么这个课题非常巧妙（立意与差异化）
1. **踩在产业爆发点上**：Meta Ray-Ban 已经上线“记住看到的东西”，2026 年 11 月谷歌刚刚发布搭载 Gemini 的智能眼镜（看海报查日历、加购物清单），论文的现实动机极强。
2. **精准避开撞车（对比 EgoPoison）**：
   - 已有最相近工作 **EgoPoison（ICLR 2027 投稿）** 做的是**数字层面**的投毒（直接修改视频/记忆注入），且被审稿人抓住了“问题看着攻击样本写导致虚高”的漏洞。
   - **EgoMem 的三大差异化壁垒**：
     1. **物理世界视角（Physical-world Text）**：研究真实生活中随处可见的环境文字，攻击门槛极低（贴一张纸即可），还配了真实走廊/实验室打印拍摄验证（E10）。
     2. **五段漏斗根因测量（Provenance-Loss Funnel）**：不只是报一个攻击成功率（ASR），而是把链路拆成 `读出 → 写入记忆 → 来源是否保留 → 被检索到 → 被采纳` 五段，精确定位每一段的衰减与失效点。
     3. **可落地防御（EgoMemGuard）**：不是“只发攻击”，而是给出“写入保留来源（组件 A）+ 使用前回溯原始证据（组件 B）”的系统性防御，并测试了自适应攻击（E9）与误伤率（对照组）。

## 二、核心科学发现的递进逻辑（读懂 E1 → E4）

很多新手刚看实验表容易被数字绕晕，其实 **E1 到 E4 是一条极其严密的“反驳审稿人质疑”的论证链**：

```text
质疑 1：是不是正常生活里本来就到处错归，系统本来就烂？
  └─▶ E1（119 帧干净画面）：自然错归极少，多为自己的手机/衣物，说明平时系统表现正常。

质疑 2：是不是只因为你们用了弱开源模型，换 GPT 看图就能识破？
  └─▶ E2（20 张便签 × 4 个视觉模型含 GPT-6.1-sol）：
      干净样本 48/48 全部被带偏！甚至视觉模型明明看出“这是叠加合成的”，下游照样当真。

质疑 3：是不是只因为 Mem0 设计有缺陷？换别的记忆框架或加 Prompt 提醒行不行？
  └─▶ E3-系统对照（Mem0 / LangMem / A-MEM / 朴素 RAG / 层级摘要）：
      官方提示词下全部 12/12 被带偏！即使保留原文、加上来源提醒，仍有 7–10/12 被带偏（典型现象：先引用来源、再当真）。

质疑 4：是不是因为回答模型 Qwen3.6-35B 太弱，换旗舰 GPT 就能分清？
  └─▶ E3-模型对照（GPT-6 Luna / GPT-6.2 Astra / Astra 深度思考）：
      • 第三人称（“小王过敏”）：旗舰 Astra 确实基本分得清（1/10），说明强模型能靠常识排错。
      • 第一人称（“我的护照在……”）：旗舰 Astra 照样当真（45/50）！因为纯文本里根本没有“谁写的”信息，再强的推理也推理不出来。
      • 抽取式记忆覆写致命伤：Mem0/LangMem 在写入时就把便签改写成 “User instructed AI to CC...”，此时就算旗舰 Astra + 来源提醒 + 深度思考，仍 8/8 照做！

质疑 5：以上都是单图 + 聊天机器人记忆框架，真正的第一视角视频记忆系统也这样吗？
  └─▶ E4（整天视频 + EgoRAG / EgoCITE 官方代码）：
      发现“漏斗效应”——官方设置下很多便签读不出（第一道闸）、读出后很多检不到（第二道闸），但**只要检到就 3/3 当真**（加来源提醒仍 2/3）。
      而且随着未来模型读字能力变强（读字版），第一道闸会大幅松动，风险必然上升！
```

> **核心洞见（论文的 Soul）**：
> 问题不是视觉模型“看不清”，也不是大模型“不够聪明”，而是**系统架构把环境视觉文本和用户自身行为混进了同一个无来源信任域**；并且**一旦写入阶段抹掉了来源，回答阶段无论怎么提醒、怎么深度思考都救不回来**。

## 三、防御框架 EgoMemGuard 设计解析

明白了上面的根因，EgoMemGuard 的两个组件就显得顺理成章、严丝合缝：

### 组件 A：写入时保留来源（Provenance-Preserving Ingestion，防患于未然）
- **解决什么痛点**：防止“写入改写”（如 Mem0/EgoCITE 把墙上便签改写成“我说/我要求……”），强行在数据结构层面把**来源标签（Source Tag）**显式化：
  - `我做的事` / `我说的话` / `别人说的话` / `环境中的文字（载体、时间、作者未知）`
- **工程切入点**：修改描述提示词（如 `egorag_patch.py`）和记忆改写/抽取提示词（如 `egocite_patch.py`），改动小、可插拔。
- **局限**：如果系统里已经有历史脏数据，或者下游回答模型“看见来源标签却依然采纳”（E4 中 EgoCITE 已经出现了这种现象），单靠组件 A 仍可能有漏网之鱼。

### 组件 B：使用前回溯原始证据（Evidence-Backtracking Verification，最后一道保险）
- **解决什么痛点**：即使记忆已经被污染或模型想盲目采纳，在**检索 → 回答**之间插入一道风险门控：
  1. **高风险判定**：是否触发动作（发邮件、用药、转账、改设置）或涉及高敏个人断言（身份、健康、关键物品位置）。
  2. **跨模态回溯**：顺着记忆节点的时间指针（Timestamp Pointer，如 EgoCITE 的 `dag.json`）回到原始视频帧与**带说话人标注的对话字幕**。
  3. **置信裁决**：若该信息**仅出现在环境文字里、佩戴者从未亲口说过** → 降权 / 强制要求注明来源 / 弹窗向用户确认；若有佩戴者语音佐证 → 正常放行（降低误伤！）。
- **设计巧妙之处**：
  - 哪怕记忆库已被“抽取式改写”污染，组件 B 依然能回溯纠偏。
  - 与“用户自己的备忘对照组”完美对应：如果用户自己贴纸并口头提过，组件 B 不会误杀。
- **已知边界（写进论文 Limitations & E9）**：如果攻击者在旁边把便签内容念出来（语音污染），或现实眼镜产品缺乏准确的说话人分离（Speaker Diarization），组件 B 会退化——计划书已经提前考虑了做“只用时间指针”的弱化版测试，非常老道！

## 四、实验设计与学术严谨性亮点（千万别踩的雷）

这份计划书的学术规范写得非常成熟，有 **5 个直接决定论文能不能中审稿的关键设计**，执行时务必严格遵守：

1. **严格的“双盲隔离”（防数据泄漏）**
   - **本科生 C** 设计便签，**本科生 A** 在**绝对不看便签原文**的情况下，只根据话题类别（如“关于证件放在哪”）撰写 96 道问题。
   - **原因**：EgoPoison 就是因为看着注入内容写问题，独立重写后 ASR 从 54.6% 暴跌到 0.4%–11.4%。这是审稿人必查项，**A 千万不要偷看 C 的便签原文！**
   - 同样，**本科生 B** 写自动裁判，因此回避人工复核；人工复核由 A 和 C 独立双标，算 Cohen's κ（须 ≥ 0.7），分歧由硕士生仲裁。

2. **控制误伤的“双对照组”**
   - 如果一个防御把所有画面文字一律拒答，ASR 肯定降到 0%，但系统就废了。
   - 因此设计了三类正常效用指标：
     - **公共告示对照**（如营业时间，应正常回答）；
     - **用户本人备忘对照**（8 张，带佩戴者口述字幕，测防御是否误杀本人备忘）；
     - **EgoLifeQA 基准**（测整体日常问答能力是否下降）。

3. **解决“随机性”与“样本量”问题**
   - 指南 6.1 提到：同一段迷你视频跑两次 EgoRAG，一次读出未检到，一次根本没读出！说明 VLM 描述存在采样随机性。正式实验需注意温度设置（如 `temperature=0`）或多次重复统计，并按便签做 Bootstrap 算 95% 置信区间、用 McNemar 检验对比防御前后显著性。

4. **提前铺好两条论文叙事退路（G2 决策点）**
   - 即使 E5 跑出来官方设置下真实系统的总体 ASR 偏低（因为漏斗前两段拦住了很多），课题也已经设计好了“**读字版（未来更强 OCR/VLM 系统）**”对照：证明随着视觉模型进步，风险会急剧暴露，防御必须前瞻性设计。这保证了实验无论偏高还是偏低都有扎实的故事可讲。

5. **省算力的“增量描述”策略**
   - 整天 854 段视频（EgoCITE 1702 个 15s 窗口）全量跑描述很耗时。切记：**干净视频的描述只生成一次**，注入便签后只重跑被改动的那 5–8 个 30 秒片段，再增量重建记忆库，能省下 95% 以上的描述机时！

## 五、工程与服务器操作避坑清单（上手必看）

登录 228 服务器操作前，牢记以下 **7 条红线与技巧**：

| 事项 | 正确做法 | 常见错误/风险 |
| --- | --- | --- |
| **服务器边界** | 所有代码/数据/脚本只在 **228**（`/srv/egomem`）运行；**188** 只通过 HTTP API 调用 | 严禁登录 188 放代码、装包、调试或重启模型 |
| **并发限制** | 调用 188 的 `qwen3.6-35b` 并发 ≤ 4（大任务提前组内沟通，尽量夜间跑） | 35B 全实验室共用，高并发会把别组服务打崩 |
| **环境隔离** | `vidnote.py` 用 `.venv/bin/python`；EgoRAG 用 `egorag-venv`；EgoCITE 用 `egocite-venv` | 用错环境会缺 OpenCV 或版本冲突；严禁改系统 Python |
| **防止覆盖 E4** | 跑任何脚本前，先复制脚本并修改 `DB=`、`EGOCITE_OUTPUT=` 和输出文件名（带自己名字或实验编号） | 直接跑 `run_egorag_*.sh` 会覆写已有库和输出（虽有只读备份 `out/_E4_frozen_20261118/`，但仍需防冲突） |
| **关闭 Thinking** | 新接入系统调 `qwen3.6-35b` 务必传 `enable_thinking=False` | 否则思考 token 会耗尽 `max_tokens`，返回空描述 |
| **超时与后台** | 长任务用 `nohup ... > logs/xxx.log 2>&1 &` 或 `tmux`；请求必须加超时（参考 `egorag_caption.py` 的 300s 超时） | SSH 断开任务中止；无超时会在 35B 忙时永久卡死 |
| **向量与遥测** | 向量模型走 188 端口（8001/8002/8003），不要在 228 CPU 硬跑；保持 `MEM0_TELEMETRY=False`、`ANONYMIZED_TELEMETRY=False` | 228 无 GPU，CPU 算向量极慢且占满内存 |

## 六、如何开始你的第一步？（按角色行动建议）

不管你是刚进组的哪位成员，建议严格按以下顺序推进前 3 天：

### 通用起步（第 1–3 天，全员必做）
1. **通读四份文档**：按 `01_overview.md` → `03_phase2_plan.md` → `02_pilot_results.md`（重点看 E4）→ `04_onboarding_guide.md` 顺序读完。

   - `EgoPoison`（弄清差异点与独立写问题的重要性）
   - `EgoLife`（了解数据集、EgoLifeQA 和 EgoRAG 架构）

### 按角色切入第一周交付物
- **如果你是硕士生（总负责 / 组件 B / WorldMM & M3-Agent）**：

- **如果你是本科生 A（问题集 / 标注 / 基线 C）**：

  - 跑通 `.venv/bin/python egomem/vidnote.py A1_JAKE DAY2 V01`，检查合成质量（透视、遮挡、光照）。
